# « Laisser tomber » : ne jamais désassigner une tâche en attente de validation

**Constat vérifié le 2026-09-16.** Le menu admin du tiroir propose `adm_release` pour une tâche `assigned` **et** `validating` (`worker_screen_tiroir.dart:471` : `if (st == "assigned" || st == "validating") options.add("adm_release")`). Un chef peut donc relâcher un travail déjà soumis, sans verdict, sans point et sans ligne au journal : un refus invisible.

**Règle voulue (2026-09-16) :** une tâche en attente de validation reste « à valider » pour le joueur tant qu'aucun adulte ne l'a jugée ; c'est le joueur qui, s'il le souhaite, finit par laisser tomber. La désassignation par un chef n'est valide que pour une tâche qui n'attend pas de validation.

**À faire.** Restreindre l'option à `st == "assigned"` dans le selector, et garder `adm_release` (`worker_admin.dart:296`) : refus si le statut lu en base est `validating`. Revoir le commentaire du selector, qui justifie l'inverse. Vérifier `adm_revive` sur une tâche `validating` (même effet de bord possible).
